# 媒体管线与导出

覆盖 FFmpeg/FFprobe sidecar 的准备与查找、媒体探测与缓存、视频音轨分离，以及预览与成片导出链路。

## 本地媒体工具（sidecar）

使用 Node 22 执行 `npm ci`，安装对应平台的 `ffmpeg-static` 与 `@ffprobe-installer/ffprobe`；Tauri 开发和发布构建会自动执行 `prepare:media-sidecars`，把经过 `-version` 校验的工具复制到 `src-tauri/binaries` 并随应用分发。

开发启动时若安装脚本未生成二进制，可复用同架构且能通过版本检查的已准备 sidecar；生产构建仍要求依赖完整。客户端按 `BVIDEO_FFMPEG_PATH` / `BVIDEO_FFPROBE_PATH`、应用资源目录、Homebrew 常见目录和 `PATH` 的顺序查找。Windows ARM64 安装包内置 x64 媒体工具，由 Windows ARM 的 x64 仿真层运行。

`src-tauri/binaries/` 中生成的二进制不手工提交，该目录只保留 README，由准备脚本生成。

## 导入、探测与缓存

桌面端提供本地视频导入、FFprobe 媒体探测、缩略图和音频波形缓存。

## 音频轨道

视频音轨可由本地 FFmpeg 分离后按原片段时间对齐到独立音效轨，也可另存为 M4A、WAV、MP3 或 FLAC。字幕识别所需的转码与分片见 [`07-云端语音.md`](07-云端语音.md)。

从音效库添加背景音乐时，若时间线上已有画面、字幕、配音或音效内容，且音乐起点早于现有内容结尾，音乐片段会自动截到这些非音乐内容的最晚结束点；音乐自身不会反向拉长这一时间范围。自动裁剪保留淡入淡出，之后仍可在时间线拖动边缘或检查器中精确调整。空时间线添加音乐时保留素材完整时长，便于先铺音乐再编排画面。

## 渲染与预览

素材与背景场景使用同一 Three.js / Canvas 确定性渲染器预览及逐帧导出。拆分和裁剪保留原运镜时间。

预览和导出复用同一组件树，并由整数微秒播放头计算确定性帧；动效元数据与注册表见 [`02-动效体系.md`](02-动效体系.md)。

## 成片导出

FFmpeg H.264/AAC MP4/MOV 成片导出，单次可设置分辨率、帧率和编码器。React 动效会在客户端按虚拟时间逐帧写入内部 RGBA PNG 缓存；帧数据以受限小批次传入本地端，减少跨进程调用。动画落定后不再重复生成相同 PNG，由本地导出链路延长末帧到图层结束，随后与视频、字幕和音频合成。产品不提供独立透明图层导出模式。

导出前会执行动效 lint，阻止未知动效、非法时间和场景层数超限；默认使用高质量编码参数，中间片段以高质量临时编码生成并通过流复制合并，减少重复有损压缩。独立视频片段会按可用 CPU 核数分配 1～4 个并发 worker，并限制每个软件编码进程的线程预算；直接使用硬件编码时最多并发 2 路，避免 CPU 超卖或耗尽硬件编码会话。

桌面导出等待视频逐帧解码，按帧写入临时缓存后由 FFmpeg 合成，可取消并清理缓存。浏览器支持素材导入与预览，保存后的无源路径素材需重新定位，成片导出仍需桌面端。

章节进度按输出帧率连续绘制，字幕与音频在同一合成步骤写入；两者的样式与数据来源见 [`01-编辑器与时间线.md`](01-编辑器与时间线.md)。
