# 应用运行时与平台集成

覆盖原生窗口集成、本地设置持久化、凭证存储，以及应用内更新的客户端行为。发布流程与更新服务端见 [`16-桌面更新发布操作手册.md`](16-桌面更新发布操作手册.md)、[`15-桌面更新服务协议.md`](15-桌面更新服务协议.md)。

## 设置持久化

桌面运行时走 `@tauri-apps/plugin-store`（`settings.json` / `preferences`），浏览器预览走 `bframe-studio:` 命名空间 `localStorage`，损坏数据回退默认值。

工程文件本身的持久化见 [`09-工程格式与持久化.md`](09-工程格式与持久化.md)。

## 凭证与密钥存储

API Key 只通过既有安全路径处理：桌面端写入应用数据目录下权限受限的凭证文件（`<app_data_dir>/credentials`，目录权限 0700，实现见 `src-tauri/src/secrets.rs`），浏览器开发预览最多使用会话级存储。不得写日志、localStorage、工程 JSON 或错误详情。

云端模型 Key 与 MiMo 语音 Key 分别独立配置，读取路径见 [`05-AI生成与动效匹配.md`](05-AI生成与动效匹配.md) 与 [`07-云端语音.md`](07-云端语音.md)。

## 原生窗口集成

仅 Windows 显示最小化/最大化/关闭按钮，macOS 保留原生红绿灯；标题栏可拖拽（`data-tauri-drag-region`）；debug 构建支持 F12 / Cmd-or-Ctrl+Shift+I 切换 DevTools。

## 应用内更新客户端行为

使用 `@tauri-apps/plugin-updater`：普通更新显示入口，`isForceUpdate` 启动即强制覆盖。

端点地址不需要单独配置：发布构建时由 `scripts/write-tauri-release-config.mjs` 从 `VITE_LICENSE_SERVER_URL` 推导，前端授权服务与 Rust 更新器消费同一个域名变量。`VITE_ENABLE_UPDATER` 严格等于 `"true"` 时才写入端点，否则端点为 `[]`——这与客户端 `src/services/updater.ts` 的判定一致，避免出现「端点已配置但被前端挡住」的死配置。环境变量含义见 [`11-本地命令与环境变量.md`](11-本地命令与环境变量.md)，协议见 [`15-桌面更新服务协议.md`](15-桌面更新服务协议.md)。

## 应用标识与命名

bundle identifier 为 `com.bframe.studio`。它决定 macOS 的签名/公证身份与 Windows 的卸载注册表项，**一旦有用户安装后就不可再改**——改动会被操作系统视为另一个应用，导致已安装用户无法升级、卸载记录无法匹配。当前尚无安装用户，因此与品牌相关的命名（存储键前缀 `bframe-studio:`、工程扩展名 `.bframe.json`、签名上下文 `bframe-license-v1`）已一次性统一到 BFrame。

发布产物文件名、目录前缀与体积口径见 [`16-桌面更新发布操作手册.md`](16-桌面更新发布操作手册.md)。
