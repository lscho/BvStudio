# Shotcraft 镜头

video-shotcraft 的 157 张配方卡已进入 BVideo 镜头库：首轮 6 个原生适配加本轮 210 个实现，共 216 个。Gallery 的 214 个样式与 Workbench 的 216 个实现采用不同计数口径；源码映射、来源哈希、时长和内容审查记录见 [迁移清单](shotcraft-migration.json)。

镜头使用内置 React 注册表和确定性帧上下文，无需 Remotion 或外部工作台。预览、工程保存和导出使用相同的镜头、图片绑定和整数微秒时钟。原 `.bveffect` 导入导出继续可用，不能将 React 镜头导出为可执行扩展包。

## 手动编辑

1. 在「动效 → 展示」搜索 `Shotcraft` 或配方名称，点击预览，点击加号加入时间线。
2. 在属性中绑定图片，支持导入、拖入、替换和排序。新库的「镜头图片（按顺序）」最多接受 12 张图片；构图仍按各配方排列，多余位置可能循环使用已绑定图片。
3. 属性提供已参数化的文字字段。首轮柔焦标题、前后对比、空间步进使用 `｜` 分隔行或步骤。新库沿用参考版式，宜使用短文案并预览完整动作。数字里程表提供 `00.00` 格式数值和独立单位；文字蒙版提供独立的中央标题，支持中文和特殊字符，并约束标题宽度。
4. 焦点巡览有四个区域；聚光悬浮卡和两种冲撞变焦有一个区域。点击截图定位或填写相对原图的百分比。冲撞变焦第一张为页面，可选第二张高清焦点图；悬浮卡可设置原位填补底色。
5. 「额外停留」增加阅读阶段的静止时间；「播放时长」调整整个镜头的速度。编辑支持撤销/重做，裁剪、拆分保留源时钟。

210 个新实现保留 1920×1080 的参考舞台，在 9:16 和 1:1 中完整等比居中，因此可能留边；不会自动重排成竖屏版式。首轮六镜仍按画幅适配。参考镜头的字体、材质和配色保留，各镜头尚未全部开放为统一主题参数。

**手动适配范围：** 42 个镜头仍包含未参数化的示例数据、品牌或界面内容，或使用参考页面的局部坐标。属性会标明需适配，AI 自动选型会排除它们。具体证据见 [AI 适配限制](../src/domain/shotcraftLibrary/aiRestrictions.json)。例如行嵌入、发牌入槽、文档打字不能仅换任意截图就保证原位拼合；部分图表不能只改标题来替换数据。其运动代码已迁入，面向任意产品的数据和版式通用化尚未全部完成。

## 转场

「衔接上一镜头」提供 10 种真实 A/B 转场：流白、整屏上推、气泡接管、对开门、立方体翻转、故障撕裂、遮挡隐切、漏光、百叶切片、时钟扫开。转场引用实际前镜末态与后镜内容，演示标题不会带入转场。库中另有 30 个转场类别的独立镜头，包含翻卡、导航和图形接管等完整场景，不等同于 30 种通用片段转场。

两段须同轨、可见、紧邻、居中、缩放 1、旋转 0、不透明度 1，无整体位置关键帧或提前弱化。关系失效时回退直接切换并在属性中提示。拆分与复制保留或更新前镜引用。

转场占用后一镜头的开头。AI 编排会让后一镜头的入场动作等待转场完成；手动添加时沿用自身时钟。上一镜头冻结在末态，不支持两段视频同时播放的重叠转场。单独增加停留不会自动推动其他片段。

## AI 编排

1. 导入图片，在顶部打开「AI 镜头编排」，填写内容与时长，选最多 12 张图片及可选背景音乐。
2. 开启图片识别时，所选图片缩成最长边 960 像素的缩略图，随文案发给已配置的云端模型。关闭时只发送素材名称和尺寸，使用默认焦点。音乐在本地分析，不上传音乐文件。
3. 第一阶段从 174 个符合自动选用条件的镜头中筛出最多 24 个候选，第二阶段接收候选的文字字段、图片槽、区域和动作锚点，生成 1–40 个分镜。支持已有 OpenAI Chat、Responses 和 Anthropic 协议，以及取消、结构校验和自动纠正。
4. 客户端校验图片槽、字段、区域、音效、重复镜头和时长。修复请求会同时附带镜头序号、字段路径、允许的文案字段与动作事件，帮助模型一次修正多个问题。所有文案字段须明确填写，不需要的使用空字符串，避免遗漏时沿用示例事实。模型仍可能误读图片，应用前需检查内容和选材。
5. 生成后展示实际编译时长、理由及未匹配动作的提示。点击「加入时间线」在指定起点新增镜头、音效和音乐轨道，以一次撤销操作写入。原字幕驱动的动效匹配入口继续使用原目录。

镜头序列不依赖事先生成口播或字幕，适合图片、界面和产品演示。AI 选择配方与参数，不生成或执行任意 React 代码。

## 音乐与声音

音频库包含 149 个 SFX 和 5 首 BGM，二进制不进入 Git。首次开发或构建前，从已安装且版本匹配的技能目录准备：

```bash
npm run prepare:shotcraft-assets -- "$HOME/.codex/skills/video-shotcraft"
# 也可通过 SHOTCRAFT_SOURCE 指定目录。
```

脚本先验证完整清单、路径和 SHA-256，再复制到被 Git 忽略的 `public/shotcraft-audio/`。应用读取时再次验证哈希；缺失时提示准备素材。桌面端使用既有音频缓存服务保存 MP3；浏览器只保留会话 URL。来源和许可见 [音频署名记录](licenses/shotcraft-audio-attribution.md)。

本地分析使用 22050 Hz PCM、频带谱通量、瞬态分类和候选网格拟合，支持 2 秒至 30 分钟、至多 200 MB 音频。网格须达到至少 98% 覆盖、平均误差低于 10 ms、漂移低于 5 ms 才使用；否则采用实际检测到的 kick/snare。分类与 BPM 属于估计，不能保证任意音乐均准确识别。音乐源入点计入所有切点。

编译器把实际转场切换时刻对齐拍点，按已核实的动作帧建立分段时钟，并预留 0.5 秒阅读停留。72 个镜头已有内部动作锚点，其余仅提供镜头边界；不能把所有末帧视为动作落点。内部锚点在 200 ms 内寻找拍点，未匹配时提示并保留动作时序；镜头切点附近无有效拍点或音乐长度不足时，停止应用并要求调整。

自动音效从筛选后的音色选择，锚定动作事件，按源文件实际 RMS 峰值校正源入点，避免前导空白造成声音延迟。相邻事件至少间隔 400 ms，整段最多 3 个冲击音效，保留尾音并在序列结尾裁齐。音效和音乐落在独立可编辑轨道，可替换、裁剪、静音及调音量。**修改镜头时长或重新排列后，声音不会自动重新卡点**；整体移动请多选镜头与音频，改变节奏后重新编排或手动调整声音。

## 工程与导出

工程为 `schemaVersion: 32`，支持 v1–v31。新增 `musicAnalyses`，Shotcraft 设置新增可选 `timeMap` 和 `leadInUs`；Zod 校验版本、单调时钟、区域、分析时长和输入上限。图片通过素材 ID 引用，会话 URL 不写入工程。

React 镜头逐帧写入既有缓存，再由 FFmpeg 合成。动效、转场、图片及整体变换烘焙到同一全画布帧。浏览器提供编辑、预览、AI 编排和音乐分析；正式成片导出仍需 Tauri 和本地源路径。

镜头舞台不继承字幕的居中样式，冲撞变焦截图显式固定相机原点。按拍点得到的非整帧片段，在原生导出中保持最后一张 PNG 至片段结束，避免末帧提前消失；片段结束后不会继续覆盖画面。

## 本轮验证

- Node 22：`npm run typecheck`、`npm test`（86 个文件、907 项测试）、`npm run build`、`npm run test:release`（42 项）通过。生产构建保留主包超过 500 kB 的体积提示。
- Rust：`cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`、`cargo check --manifest-path src-tauri/Cargo.toml` 通过。新增 `streamed_overlay_covers_the_last_fractional_frame` 实际 FFmpeg 回归测试，检查片段结束前后两帧，并分别使用系统与随应用准备的 FFmpeg 验证。
- 画面：210 个新实现的首中尾单元渲染、420 个浏览器采样帧、三画幅转场、深浅主题和矮窗口；冲撞变焦两种样式追加横屏、竖屏、方形检查。
- 样片：4 个新增镜头与真实产品截图，经正式 React 栅格化和 FFmpeg 合成得到 18.33 秒、960×540、30 fps、550 帧的带音乐及仅音效两版。两版画面一致；独立复核确认推近构图和最后一帧正常。结尾字标完全静止约 0.53 秒，正式宣传片可增加停留。
- 声音：3 个切点按实际音乐瞬态编排，4 个动作音效的编码后 RMS 峰值偏差为 3.5–7.5 ms，背景音乐对原音源无采样偏移。此结果仅针对本样片，不代表任意音乐的识别精度。

追加真实云端实测：通过配置的 Responses 服务与 `gpt-5.6-terra`，围绕「AI 剪辑的痛点与 BVideo 的解法」生成 11 镜、50 秒计划。实际加入时间线后为 50.05 秒，包含 4 条动作音效和 1 条音乐；撤销清空、重做恢复及工程序列化校验通过。云端测试暴露了泛化错误反馈和重复镜头未强制校验的问题，已增加回归测试并修复。

实测使用浏览器编辑器；浏览器跨域请求由 Playwright 转发至真实服务，响应内容未模拟。期间出现网关超时与上游流失败，不把 HTTP 200 等同于有效计划。展开候选为大型联合 schema 的试验已撤回，保留紧凑协议结构与本地严格校验。输出为 50.07 秒、1080p、30 fps 的带音乐及仅音效两版，两版视频流一致；音乐回测无采样偏移，4 条音效峰值偏差约 0.9–6 ms。追加前端完整测试为 911 项通过。

该云端样片通过技术流程验证，但未通过发布质量验收。模型选型仍可能带入默认标签或让功能信息只停留在分镜理由中；部分截图缩得过小，扫描类镜头沿用空占位页面，长品牌字标的构图与停留仍需适配。中文无空格时的首词动画、时间轴巡览的末尾推近时长也有待进一步处理。频谱类模板的运动并非来自实际音频 FFT，不能把音乐卡点与真实频谱驱动等同。品牌样式、功能完整性和镜头运动需要逐镜审查。

Tauri WebKit 与原生 IPC 完整导出、Windows/Linux 尚未实测。样片经过 React 帧导出和 FFmpeg 编码，不等同于桌面端全流程验收。
